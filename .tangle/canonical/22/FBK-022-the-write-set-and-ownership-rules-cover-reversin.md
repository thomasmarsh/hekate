# Feedback

Attempted: Executing TAS-049 slice D: producing Fast/Standard/Fine convergence evidence and replay --verify on the manifests behind it. The reproduction script's replay step found that run_batch recorded BatchRequest::step_s in every run manifest but ran the kernel at the default step, so a Fast batch held a manifest naming 0.1 s and a stream header naming 0.05 s. The fix belongs to a resolved slice (TAS-035 owns run_batch, TAS-041 owns the convergence runner whose evidence the defect falsified), and the skill has no rule for who owns regenerating a resolved node's derived artifacts once a later fix invalidates them.
Friction: The write-set and ownership rules cover reversing an outcome in its own node (in-place reversal, context_rev bump) and superseding an outcome that moves to a new node, but not the case this session hit: a later slice must change code a resolved slice owns in order to make its own deliverable true, which regenerates artifacts that resolved slice committed (convergence_evidence.json, convergence_summary.md) and updates a test that resolved slice wrote (tests/converge.rs asserted a material sensitivity that only appeared because Fast and Fine ran at the wrong step). The skill leaves the ownership and the reporting obligation implicit: TAS-049 does not own TAS-035, and nothing says whether the fix is a new node, a reversal recorded in TAS-035, or a Result entry in the discovering node. The exclusive write set given to the worker named only converge.rs and the evidence artifacts, so batch.rs was reachable only through the "related CLI modules" phrase.
Improvement: Add a short rule to SKILL.md under reversal and supersession or under the node boundary: when a later node must change behavior a resolved node owns for its own outcome to hold, the discovering node performs the change, records the defect, the falsified artifact, and the regenerated artifact names in its own Result, and the resolved node is left untouched (read-only) because its body still describes what it did at the time; if the change is separable and independently resumable, admit a child or a sibling node instead and name the resolved owner in its Context. State explicitly that derived artifacts of a resolved node may be regenerated by the node that re-derives them, and that the regeneration is reported like a golden regeneration.
