# Feedback

Attempted: Ran Phase 2 Increment 2 TAS-020 as a serial fresh-worker orchestration (lateral/return work, wrong-way travel, event surface, close-pass metrics) with a timed-out-worker recovery per leaf.
Friction: Seven frictions. (1) Worker loop cost: briefs required `cargo test --workspace` as per-leaf acceptance; one touched test binary is 34-37s (tick-loop integration tests) and the full workspace gate is 150-300s over 83-85 test binaries, so many dispatched workers hit the 30-minute harness timeout. (2) Timed-out-recovery write set: a finisher brief said "remove scratch only", but `cargo clippy -D warnings` and `fmt` were red on retained-slice lines outside the scratch test, so the finisher had to make repairs the brief did not authorize. (3) `git mv` stages the pre-edit blob, while the brief said do not `git add`; the staged rename carried a stale blob that no longer matched the written `# Result`. (4) Slice sizing: several leaves (TAS-113, TAS-114, TAS-117, TAS-122, TAS-123) were multi-hour outcomes dispatched as one leaf and each exceeded a session; the size-slices-up-front rule was applied only after timeouts. (5) The installed `tangle` upgraded mid-session (0.6.0+gef4b49d -> 0.6.0+g3e6479b): `tangle node record` then wrote `.tangle/canonical/5f/tas-<random>.md` with a frontmatter `status:` field and no `<PREFIX>-NNN` filename, plus an untracked `.tangle/project-id`, instead of the repo's status-directory layout; the stray file and directory had to be deleted and the node hand-authored, and `tangle check` still counted the non-canonical node. (6) `tangle allocate DEF` before `record` burns the returned id (no read-only preview, no `record --dry-run`), and `node record` with no `--route` silently inserts a default `Area [[IDX-001-hekate]]` line, so a body that already authors its `Parent` route ends up with two primary routes that only a hand edit removes. (7) A worker created an `FBK` node without a coordinator grant; the one-per-session rule then required fold-and-delete into the coordinator's node.
Improvement: (a) Make per-leaf acceptance the touched test binary only and reserve `cargo test --workspace` for the coordinator gate; note that cargo-nextest plus a pruned `target/` (25 GB) would cut the loop. (b) A timed-out-recovery brief must state explicitly whether the finisher may repair clippy/fmt failures in the retained partial slice. (c) Permit `git add` of the destination after `git mv`, or state that the integrator stages the renamed blob. (d) Split a multi-hour increment leaf before dispatch (state the deliverable, keep each slice to one session) instead of detecting the overrun at the worker timeout. (e) Pin or warn on a mid-session `tangle` upgrade, and make `node record` write the status-directory layout and omit a default route when the body already carries a primary `Parent`/`Area`. (f) Add a non-burning id preview or `record --dry-run`, and document that `allocate` before `record` burns the id. (g) State in the worker brief that only the coordinator records `FBK` nodes.
