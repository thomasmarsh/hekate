# Outcome

Deterministic tests cover the shared presentation layer and each terminal
backend, and prove that backend choice and frame pacing cannot change simulation
results.

# Done when

- Shared scene projection and `ViewCommand` handling have golden snapshot tests
  built from fixed simulation snapshots.
- The character backend has checked-in golden character grids for a fixed
  scenario, seed, viewport, and tick, regenerated by a script and compared
  byte-for-byte.
- The Kitty backend has golden byte fixtures for framing, chunking, placement,
  and deletion, needing no real terminal.
- A parity test drives one seed through the Bevy clock, the terminal clock, and
  direct stepping and asserts identical tick sequences and trace hashes.
- Capability fallback preserving playback state is covered by test.

# Result

All Done-when criteria are met. The deterministic renderer suite is
`crates/hekate-present/tests/scene_golden.rs`,
`apps/hekate-tui/tests/golden_cells.rs`,
`apps/hekate-tui/tests/golden_kitty.rs`, and
`apps/hekate-tui/tests/clock_parity.rs`, with checked-in goldens under
`tests/golden/present/` and `tests/golden/renderer/`.

- Shared scene projection and `ViewCommand` handling: `scene_golden.rs` pins
  the full `SceneFrame` for the walking scenario at seed 0 and tick 20 with a
  half-step interpolation, and pins the observable controller state after
  pause, single-step, speed, pan, zoom, selection, both overlays, clear, and a
  restart request.
- Character grid: `golden_cells.rs` captures the grid through the real
  `TuiSession`/`CellBackend` path for the walking scenario at seed 0, tick 20,
  and 80x24, and compares `CellGrid::to_ansi(Truecolor)` byte-for-byte with a
  checked-in golden. Regenerating needs `scripts/regen-goldens.sh`.
- Kitty bytes: `golden_kitty.rs` pins command framing (including empty-payload
  and tmux/screen wrapping), a four-chunk transmission, a full
  transmit-plus-stable-placement frame with the HUD, and image deletion, all
  through the `Write` sink with no real terminal.
- Tick and trace parity: `clock_parity.rs` runs one seed by direct stepping,
  the Bevy viewer's irregular frame partition, and the terminal session's many
  small frames, and asserts every leg reaches 20 ticks and the same canonical
  trace hash. A second test drives the real `TuiSession` on that partition and
  matches the direct `Simulation` snapshot at tick 20.
- Capability fallback:
  `fallback::tests::a_session_keeps_playback_state_across_a_real_capability_fallback`
  runs a `TuiSession` over `BackendPair` with a real `KittyBackend` under a GNU
  screen multiplexer, so the backend really declines; the session switches to
  character cells and keeps its tick, speed, pause, and selection.

Supporting API added to make the suite possible: `hekate-cli` exposes
`TraceRecorder`, so a clock-driven run records the same canonical trace bytes
as `canonical_trace`; `CellBackend::grid()` returns the last drawn grid and
`TuiSession::draw()` splits drawing from presenting; and `hekate-tui`
re-exports the Kitty framing primitives the byte fixtures exercise.

# Evidence

The CLI golden trace is unchanged after the `TraceRecorder` refactor
(`checked_in_walking_trace_matches_golden_bytes_and_hash` and
`same_seed_produces_the_same_hash_twice` pass).

`cargo fmt --all --check`, `cargo clippy --workspace --all-targets
--all-features -- -D warnings`, `cargo test --workspace --all-features`, and
`./scripts/check-dependency-direction.sh` are clean. New tests: 2 scene
goldens, 1 character-grid golden, 4 Kitty byte fixtures, 2 clock-parity tests,
and 1 real-backend fallback test. `scripts/regen-goldens.sh` writes the five
golden files and `UPDATE_GOLDENS` is unset for normal runs, so the compared
bytes are always checked in.
